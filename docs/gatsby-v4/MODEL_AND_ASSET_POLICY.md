# Asset regeneration policy

- Regenerate only where an input is deficient. Replacing every image indiscriminately can destroy product, person or location continuity and legitimate restoration challenges.
- Raster regeneration uses the connected image-generation tool. The exact underlying model identifier was not exposed in this run; no claim of using an unverified model name is made.
- A single canonical product/person/location reference must govern each regenerated set. Check geometry, labels, materials, lighting and continuity before replacing the existing input pack.
- Logos supplied for ordinary composition must have usable transparent artwork. Native vector geometry and properly outlined typography are preferable to an AI-generated picture of a logo.
- Intentional identity-recovery tasks retain damaged references. Do not give participants an already-completed recovered master; any evaluator reference is kept outside the participant pack.
- Source photos for archives, named properties, real-looking testimonials and training actions must not gain invented factual detail. Synthetic benchmark assets must be labelled as such in provenance.
- Video generation and speech synthesis are not exposed by the current connected Adobe tools. No provider API key is configured in the current execution environment. Missing footage/audio remains a release blocker, not a reason to count silent placeholders as finished work.
- No chat-pasted credentials are persisted, committed or copied into logs. Replacement provider credentials should be configured locally after rotation.
